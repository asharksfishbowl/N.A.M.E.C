# Spec: Authored Map

## Overview
N.A.M.E.C ships one hand-authored voxel map instead of seeded, generated worlds. This spec owns how that map is authored, baked, versioned, validated, loaded and patched, and it replaces every "world generation" rule in the other system specs with a cross-reference to itself. Decided in the 2026-09-16 round table (`transcripts/roundtable-2026-09-16-*.md`); shared terms are defined in `specs/game-foundation/game-foundation.md`.

## Goals
- One map, fully diggable smooth-voxel terrain (`specs/voxel-world/voxel-world.md` Requirements 1–4), authored by a person in the editor and reproducible from versioned inputs.
- A player's world survives a map patch: terrain edits replay onto the new base, and nothing a player built is deleted by an update.
- Expansion content lands later as gated regions on the same map, unlocked by a map revision.
- Every authoring input is plain-git versionable from the pipeline container; the baked map is a derived artifact produced on the reference PC.
- One source of truth: how base voxel data reaches a chunk is written here and nowhere else.

## Non-Goals
- Runtime world generation of any kind. `UNamecWorldGenerator` as a runtime class does not exist. The only seeded procedures are the bake-time cave and ore passes (Requirement 8a) and runtime PCG scatter (Requirement 21), both keyed by `AuthoringSeed`.
- Multiple maps, a second-map loading hook, or a map selection screen. There is one map asset per build.
- Infinite terrain, world size options, or a runtime world-size setting.
- An in-game map editor. The sculpt brush is editor-only.
- Choosing the terrain mesh backend (roadmap decision, `specs/engine-tech/engine-tech-roadmap.md` "Terrain mesh backend").
- Choosing the placeholder art source, or adopting Git LFS. LFS is deferred to the first phase that ships real art (Requirement 33).

## Requirements

### Map asset
1. The map is one `UNamecVoxelMapAsset` (`Source/NAMEC/World/Map/NamecVoxelMapAsset.h`), a `UPrimaryDataAsset`, holding: a `MapId` (`FGuid`, fixed for the life of the map and never changed by a patch), an integer `MapRevision` (starts at 1, incremented by hand for every shipped change to the baked data), a `BaseChunkHashes` table (SHA-256 per chunk over that chunk's **uncompressed** base voxel values, so a compressor change never produces a false mismatch), a `MapHash` (SHA-256 over the `BaseChunkHashes` values in chunk-coordinate order), the world extent in metres (fixed authored constant, one value for both horizontal axes), the bedrock depth in metres (replaces "per world size" in `specs/voxel-world/voxel-world.md` Requirement 16), the voxel resolution (25 cm, `specs/voxel-world/voxel-world.md` Requirement 3), the integer `AuthoringSeed` used by the bake passes and by runtime PCG (Requirements 8a, 21, 23), and the baked voxel data itself, stored per chunk and compressed.
2. The baked voxel data is a derived artifact. The asset file `Content/Map/Baked/VMA_Namec.uasset` is gitignored (folder rule `Content/Map/Baked/**`) and is produced by running the bake commandlet (Requirement 8) on the reference PC. A fresh clone plus one bake run reproduces the asset byte for byte (Acceptance Criteria).
3. The benchmark milestone (`specs/engine-tech/engine-tech.md` Requirement 11) uses a second, smaller map asset, `Content/Map/Baked/VMA_Benchmark.uasset`, 1 km × 1 km, built from the same input format and the same bake commandlet. It is the Phase 1 map. `VMA_Namec` exists from Phase 4 onward (roadmap).
4. Only one map asset is the shipped map at a time. `Config/DefaultGame.ini` names it under `[/Script/NAMEC.NamecMapSettings]` as `ShippedMapAsset`. `ANamecVoxelWorldActor` has a `TSoftObjectPtr<UNamecVoxelMapAsset> MapAssetOverride`; the **effective map asset** is the override when set, otherwise `ShippedMapAsset`. The benchmark level `L_Benchmark_SplitScreen` sets the override to `VMA_Benchmark`. Every rule in this spec that says "the map asset" means the effective map asset.

### Authoring inputs (versioned)
5. Every authoring input lives under `Content/Map/Source/<MapName>/` in plain git, no LFS filter:
   - `Heightfield/` — present only when `HeightfieldSource` is `Tiles`: 16-bit greyscale PNG tiles at 1 m per pixel, each tile at most 10 MB on disk, named `H_<x>_<y>.png` by tile column and row.
   - `Masks/R_<x>_<y>.png` region tiles (8-bit, one value per climate region row in `DT_World_Climates`, 1 m per pixel) and `Masks/M_<x>_<y>.png` surface material tiles (8-bit, one value per `DT_World_VoxelMaterials` row), on the same tile grid and naming as the heightfield. When `HeightfieldSource` is `Noise`, both masks may be omitted and `BakeSettings.json` names one region and one surface material for the whole map.
   - `Strokes.namecstrokes` — the stroke log (Requirement 6).
   - `BakeSettings.json` — `MapId`, `MapRevision`, `AuthoringSeed`, world extent, bedrock depth, voxel resolution, tile grid dimensions, `HeightfieldSource` (`Tiles` or `Noise`), the heightfield's vertical scale and offset in metres, the noise parameters when `Noise` (octave count, base frequency, amplitude, sea level), and the cave and ore pass parameters (Requirement 8a) that are not per region.
6. The stroke log is a UTF-8 text file, one stroke per line, append-only, with a header line `namecstrokes v1`. Each line is: `<order> <centre_x> <centre_y> <centre_z> <radius_m> <mode> <material_row> <tool_tier>`, space-separated, where `order` is a strictly increasing integer, coordinates and radius are metres in map space, `mode` is `Dig` or `Fill`, `material_row` is a `DT_World_VoxelMaterials` row name (ignored for `Dig`), and `tool_tier` is an integer. Unknown versions, non-increasing `order`, an unknown `mode` or an unknown `material_row` fail the bake with the line number (Edge Case 1).
7. The stroke log is the second caller of the shared voxel write kernel, `FNamecVoxelWriteKernel` (`Source/NAMEC/World/NamecVoxelWriteKernel.h`), whose first caller is the runtime dig/fill path (`specs/voxel-world/voxel-world.md` Data Flow 3). The runtime calls the kernel after validation (tool tier, town protected radius, dig depth limit, gated expansion regions per Requirement 26); the bake calls the kernel with no validation, on the whole map, in stroke order. The kernel is the only code that applies a sphere edit to voxels. Voxelisation and the bake passes (Requirement 8a) write density and material before any stroke and do not go through the kernel. Voxels written by a bake stroke are not flagged player-placed.

### Bake tool
8. `UNamecMapBakeCommandlet` (`Source/NAMECEditor/Map/NamecMapBakeCommandlet.h`, editor module) is run as `UnrealEditor-Cmd.exe NAMEC.uproject -run=NamecMapBake -Map=<MapName>`. It: reads `BakeSettings.json`; voxelises the heightfield (tiles, or noise per Requirement 5) into a signed-density field with the region and material masks applied; runs the cave pass and then the ore pass (Requirement 8a); replays the stroke log through the write kernel, so strokes override the passes; computes `BaseChunkHashes` and `MapHash`; writes `Content/Map/Baked/VMA_<MapName>.uasset`; and prints the `MapHash`, the chunk count and the elapsed time. Exit code is 0 on success and non-zero on any Edge Case 1–3 failure.
   The bake is **tiled**: it holds in memory one tile plus a halo equal to the largest stroke radius in the log, never the whole map. Every voxelisation and pass computation is therefore a pure function of `AuthoringSeed`, the voxel's map position, and the region's parameters, with no state carried between voxels or tiles. Iterative algorithms (cave walkers, growth from a start point) are not permitted in a bake pass.
   8a. **Cave pass and ore pass.** Caves are carved by a stateless noise function of `AuthoringSeed` and voxel position, thresholded per region with the cave density, depth band and tunnel radius columns of `DT_World_Climates`; the pass only carves below the surface and above bedrock. Ore is placed by a stateless hash-based vein function of `AuthoringSeed` and voxel position driven by `DT_World_OreVeins` (`Content/Data/DT_World_OreVeins.uasset`), whose rows are: region, ore material row (`DT_World_VoxelMaterials`), vein density, vein radius in metres, and a cave-only flag (true rows place ore only in voxels adjacent to cave air, satisfying `specs/voxel-world/voxel-world.md` Requirement 10's higher-tier cave ore). The function assigns ore only to stone voxels within the dig depth limit of the nearest base air above them, so the Requirement 10 ore check is satisfied by construction and the check catches only regressions. `AuthoringSeed` thus has two consumers: these passes and runtime PCG (Requirement 21).
9. Two bake runs over identical inputs produce a byte-identical asset and the same `MapHash`. The bake uses no randomness other than `AuthoringSeed`-derived hashing, no timestamps, and no machine-specific paths in the asset.
10. After the passes and the stroke replay, the bake checks two terrain guarantees that generation used to provide and fails the bake if either is violated (Edge Case 3): every ore voxel (a `DT_World_VoxelMaterials` row flagged ore) is within the dig depth limit of `specs/voxel-world/voxel-world.md` Requirement 34, measured on the baked data, checked per column; and every cave air voxel (base air whose column has solid base voxels above it) connects through base air to the map's top voxel layer, checked by a flood fill over the cave-air set only, joined across tiles by a chunk-level connectivity graph. The failure report lists the first 20 violating voxels by map coordinate.
11. `UNamecDigDepthQuery` (`specs/voxel-world/voxel-world.md` Requirement 34) reads the baked base voxel data. "Generated air" in that spec now means a voxel that is air in the baked base data, player edits ignored. Its rules are otherwise unchanged.

### Sculpt brush (editor-only)
12. `FNamecSculptBrushEdMode` (`Source/NAMECEditor/Map/NamecSculptBrushEdMode.h`) is an editor mode that lets the author dig or fill a sphere in the level viewport with the same radius, mode, material and tier parameters as a stroke. Each brush application appends one line to `Strokes.namecstrokes` and applies the same stroke to the in-editor preview through the write kernel. The brush never writes the baked asset; the baked asset changes only through the bake commandlet.
13. The sculpt brush is not part of Phase 1. Phase 1's benchmark stroke log is hand-written (a test pit and a cave mouth) and committed as text.

### Map validator (editor-only)
14. `UNamecMapValidator` (`Source/NAMECEditor/Map/NamecMapValidator.h`) is a Data Validation validator that runs on the shipped map's level (Requirement 16's actors) on level save and under the engine's Data Validation commandlet (named in the handover note), and fails validation when any rule below is broken. Each failure names the actor and the rule. Rules that read region require the baked asset; when it is missing, validation fails with "bake the map first". The validator never runs inside the bake commandlet. Rules 1–9 run only on a level whose effective map asset (Requirement 4) is `ShippedMapAsset`; rule 10 runs on every level that contains a structure actor, including `L_Benchmark_SplitScreen`.
    1. Each kingdom in `specs/factions-kingdoms/factions-kingdoms.md` Requirement 13 has exactly one `ANamecTown` with `bIsCapital` true and exactly two with it false, all inside the kingdom's home region as read from the baked region mask at the actor's position.
    2. No `ANamecTown` exists inside the Snowy Mountains or Volcanic region.
    3. No town protected radius (`specs/factions-kingdoms/factions-kingdoms.md` Requirement 15) overlaps another town's protected radius, an `ANamecBossArena` radius, or the world spawn point's building-blocked zone (`specs/voxel-world/voxel-world.md` Requirement 28).
    4. No `ANamecCamp` centre is inside a town protected radius, a boss arena radius, or the world spawn point's building-blocked zone.
    5. Each `ANamecTown` has exactly one Quest Board component and at least one NPC post whose row is a Vendor; each capital has exactly one Quest Giver post and exactly one Guard Captain post; each non-capital town has at least one Quest Giver post (`specs/factions-kingdoms/factions-kingdoms.md` Requirement 16).
    6. Each of the eight climate regions has exactly one `ANamecBossArena` whose position is in that region.
    7. No `ANamecTown`, `ANamecCamp`, `ANamecBossArena` or `ANamecRuin` is inside an `ANamecExpansionRegion` (Requirement 26).
    8. Exactly one `ANamecWorldSpawnPoint` exists and it is in the Temperate Forest & Meadows region (`specs/voxel-world/voxel-world.md` Requirement 9).
    9. The Temperate region contains the map centre.
    10. No two `UNamecStructureIdComponent`s in the level share a `StructureId` (Requirement 16).
15. Rules that `DT_World_Structures` used to hold as placement data (per-region camp density, placement search rules, per-structure post and chest positions) are removed. `DT_World_Structures` keeps only per-type data: the town protected radius and the default component set the editor spawns when an author places a new structure actor of that type. Camp radius stays in `DT_Factions_Factions` (`specs/factions-kingdoms/factions-kingdoms.md` Requirement 17), unchanged.

### Authored structures
16. Capitals, towns, camps, ruins and boss arenas are actors placed in the editor on the shipped map's persistent level, `Content/Maps/L_Namec.umap`. Classes, all in `Source/NAMEC/World/Structures/`: `ANamecTown` (fields `bIsCapital`, `Kingdom`, `ProtectedRadius`; child components: one `UNamecQuestBoardPost`, `UNamecNPCPost` per post each naming a `DT_Factions_NPCs` row), `ANamecCamp` (fields `Faction`, `CampRadius`; child components: `UNamecEnemySpawnPoint` per spawn point, `UNamecLootChestPoint` per chest), `ANamecRuin` (child `UNamecLootChestPoint` components), `ANamecBossArena` (fields `Region`, `ArenaRadius`; no altar component — save state keyed by `UNamecStructureIdComponent` per the general rule above), and `ANamecWorldSpawnPoint`. Every structure actor that owns save state (`ANamecTown`, `ANamecCamp`, `ANamecRuin`, `ANamecBossArena`, standalone `ANamecLootChestPoint`) carries a `UNamecStructureIdComponent` (`Source/NAMEC/World/Structures/NamecStructureIdComponent.h`) holding a `StructureId` (`FGuid`) generated when the actor is placed, regenerated by the component when the actor is duplicated, and read-only in the editor. `ANamecWorldSpawnPoint`, `ANamecWaterVolume` and `ANamecExpansionRegion` hold no save state and have no `StructureId`. Save data about a structure (camp cleared state and respawn timer; Vendor stock; Quest Board offers; NPC respawn timers; boss-defeat state) is keyed by `StructureId`, never by actor name or level index. Save data about a component inside a structure (a spawn point's dead state, a chest point's opened state) is keyed by the owning actor's `StructureId` plus the component name, which the engine keeps unique within an actor.
17. Everything the other specs describe as "placed by generation" for these structures now reads the actor's fields and child components: `UNamecTownSubsystem` enumerates `ANamecTown` actors (replacing `specs/factions-kingdoms/factions-kingdoms.md` Data Flow 1's placement step), camp streaming reads `ANamecCamp` spawn points (`specs/factions-kingdoms/factions-kingdoms.md` Requirement 18), and boss summoning reads `ANamecBossArena` (`specs/combat-loot/combat-loot.md` Requirement 23). World-creation initialisation of Vendor stock, Quest Board offers, NPC respawn timers and camp states is unchanged except that its input list is the authored actors.
18. Town buildings are static meshes owned by the `ANamecTown` actor's level (authored content under World Partition when adopted, or children of the actor until then). They are not building pieces and are neither damageable nor deconstructable (`specs/factions-kingdoms/factions-kingdoms.md` Requirement 14, unchanged).
19. Loot chest positions in caves that are not part of a ruin or camp are `ANamecLootChestPoint` actors placed by the author. There is no deterministic cave chest placement.
20. Water stays a static liquid volume (`specs/voxel-world/voxel-world.md` Requirement 7): author-placed `ANamecWaterVolume` actors (`Source/NAMEC/World/Structures/NamecWaterVolume.h`) with a `WaterKind` of Fresh, Salt or Poison. Water is not a voxel flag and there is no water mask. The ocean is one Salt `ANamecWaterVolume` at sea level covering the whole border, over terrain the heightfield takes below sea level around the map edge. `ANamecVoxelWorldActor` clamps every player pawn's position to the rectangular world extent (Requirement 1), so the world boundary rule is unchanged.

### Runtime placement (PCG)
21. Trees, forage nodes, loose pickups, collidable rocks, props and cosmetic vegetation stay runtime PCG placement, run per streamed chunk (`specs/engine-tech/engine-tech.md` Requirement 3, PCG Framework row). Every PCG graph under `Content/World/PCG/` reads its seed as one 32-bit hash of the map asset's `AuthoringSeed` and the chunk's integer X and Y coordinates (written `HashCombine(AuthoringSeed, ChunkX, ChunkY)` in this spec), so the host and every client produce identical placement for the same chunk (Acceptance Criteria).
22. PCG graphs read the authored exclusion volumes and place nothing inside: every `ANamecTown` protected radius, `ANamecCamp` camp radius, `ANamecBossArena` arena radius, the world spawn point's building-blocked zone, and every `ANamecExpansionRegion`. Exclusion is evaluated in the PCG graph, not by deleting spawned actors afterwards.
23. `AuthoringSeed` is an authoring input in `BakeSettings.json`. Changing it is a map revision (Requirement 27) because it changes every cave, ore vein and tree position, and therefore every saved tree harvest state's referent.

### World save and load
24. `UNamecWorldSave` (`specs/game-foundation/game-foundation.md` Requirement 6) drops `seed` and `size` and gains: `MapId` (`FGuid`), `MapRevision` (integer), `MapHash` (SHA-256) copied from the map asset at world creation and rewritten on every save, and `EditedChunkBaseHashes`: for every chunk that holds at least one edit delta, that chunk's `BaseChunkHashes` value recorded when the chunk's first delta was written, and rewritten to the current asset value after a Requirement 25.2 load. Chunks with no deltas have no entry, and a chunk re-baked into a snapshot (`specs/voxel-world/voxel-world.md` Edge Case 8) keeps its entry. The save also gains `PendingTerrainMarkers`: a list of chunk coordinates, added by load rule 25.2, removed when a player interacts with that chunk's marker, and spawned as `ANamecTerrainUpdatedMarker` actors on every load while present. This is a `SaveVersion` bump with a migration that fills the new fields from the shipped map asset and an empty marker list (`specs/game-foundation/game-foundation.md` Requirement 7).
25. Load rule, evaluated by `UNamecWorldLoader` (`Source/NAMEC/Save/NamecWorldLoader.h`) before any chunk streams:
    1. Save `MapId` ≠ shipped map asset `MapId` → refuse the load, show "This world belongs to a different map", return to the main menu, leave the file untouched.
    2. Same `MapId`, save `MapRevision` < asset `MapRevision` → load. The loader touches no voxel data: it compares `EditedChunkBaseHashes` against the asset's `BaseChunkHashes`, and for each mismatched chunk writes one log line naming the chunk and adds the chunk to `PendingTerrainMarkers`. Edit deltas apply onto the new base as each chunk streams (Requirement 29); deltas are absolute per-voxel values, so applying them onto a changed base is always valid. Show "World updated to map revision N" once, on the host's viewport, after the world loads. Each pending chunk spawns one replicated `ANamecTerrainUpdatedMarker` at the chunk's centre, visible to every player. The marker implements the same interactable interface as doors and Quest Boards (`specs/game-foundation/game-foundation.md` Requirement 14 Interact input); the existing interact server RPC removes the chunk from `PendingTerrainMarkers` and despawns the marker. No new RPC is added. Rewrite the save's `MapRevision`, `MapHash` and `EditedChunkBaseHashes` on the next save; `PendingTerrainMarkers` persists until each entry is cleared by interaction.
    3. Same `MapId`, same `MapRevision`, `MapHash` ≠ asset `MapHash` → load normally and write one warning log line. No message and no markers (this is the developer-iteration case).
    4. Save `MapRevision` > asset `MapRevision` → refuse with "This world was saved with a newer version of the map", leave the file untouched (mirrors the newer-`SaveVersion` rule).
    No load rule ever discards an edit delta.

### Expansion placeholders
26. An `ANamecExpansionRegion` (`Source/NAMEC/World/Structures/NamecExpansionRegion.h`) is an author-placed volume with a `bGated` flag. While gated: the volume is a blocking volume from bedrock to the map's top voxel layer that blocks every pawn (players, enemies, raiders, NPCs), with a navmesh Null area modifier so no AI path enters it; no terrain edit is accepted for a voxel inside it (the server removes those voxels from the edit like a town protected radius, `specs/voxel-world/voxel-world.md` Requirement 37, with the HUD text "Unexplored" in the acting player's viewport only); no PCG placement occurs inside it (Requirement 22); no structure actor may sit inside it (Requirement 14.7); and no enemy spawns inside it (`specs/combat-loot/combat-loot.md` Requirement 20 spawn exclusion). Its terrain is baked like any other terrain and renders normally from outside.
27. Unlocking an expansion is a map revision: the author sets `bGated` false, authors the content, and increments `MapRevision`. Because no edit delta can exist inside a gated region, no `EditedChunkBaseHashes` entry can refer to a chunk changed by the unlock unless the chunk straddles the boundary (Edge Case 6).

### New World flow
28. New World (`specs/game-foundation/game-foundation.md` Requirement 11 and Data Flow 2; `specs/voxel-world/voxel-world.md` Requirement 5) takes: world name and world settings (friendly fire, LAN hosting and password, Raids). Seed and size inputs are removed from the flow and from the UI. The world save is created with `MapId`, `MapRevision` and `MapHash` from the shipped map asset, the voxel resolution copied from the asset into the save (`specs/voxel-world/voxel-world.md` Requirement 3 still reads it from the save), an empty edit list, an empty `EditedChunkBaseHashes` and an empty `PendingTerrainMarkers`.

### Chunk streaming
29. `UNamecVoxelWorld` (`specs/voxel-world/voxel-world.md` Data Flow 2) streams a chunk by decompressing that chunk's base voxel data from the map asset and then applying the chunk's stored edit deltas (or its compressed snapshot, `specs/voxel-world/voxel-world.md` Edge Case 8). There is no runtime generation step.

### Repository and pipeline shape
32. Repository rules, delivered as Phase 1 task 1 deliverables: `.gitignore` ignores `Content/Map/Baked/**` and `Content/Placeholder/**` (folders, never `*.uasset`); `.gitattributes` marks `*.uasset` and `*.umap` as `binary` and contains no `filter=lfs` line; a pre-commit hook at `Tools/Hooks/pre-commit` rejects any staged file over 20 MB with the file name and size, installed per clone with `git config core.hooksPath Tools/Hooks` (a step in the task 1 handover note).
33. Third-party placeholder art (Epic Mannequins, engine starter content, Fab assets) lives under `Content/Placeholder/` and is never committed. Project-authored uassets (levels, data tables, Geometry Collections, PCG graphs, Mutable objects, Motion Matching databases, StateTrees, exported test meshes) are committed to plain git by the user on the task's sub-branch. Every C++ reference to a placeholder asset goes through a `TSoftObjectPtr` column in a data table, never a hard-coded path. Git LFS is decided in the first phase that ships real art, not before.
34. Every Phase 1 task ends in state "awaiting verification" with a handover note from the template `Tools/Handover/HANDOVER_TEMPLATE.md` (a task 1 deliverable) holding: the engine classes and functions the task assumed; the exact commands to compile, run automation tests, run commandlets or open PIE; the single command or test that proves the task's core claim; and for each asset the task needs, its source, asset name and exact Content path. The user pastes results back; the sub-branch merges to `feature/benchmark-milestone/base` only after that.
35. Task 12's `ANamecBenchmarkDirector` writes `Saved/Benchmark/<timestamp>/content-manifest.json` beside `results.json`: every asset under `Content/Benchmark/` and `Content/Placeholder/` with its SHA-256, plus the benchmark map asset's `MapHash`. The roadmap's Benchmark Results table gains a "Manifest hash" column holding the SHA-256 of that file.

## Data Flow
1. Author edits heightfield and mask tiles in an image tool, or sculpts with `FNamecSculptBrushEdMode` (appending to `Strokes.namecstrokes`), and edits `BakeSettings.json` → commits `Content/Map/Source/<MapName>/` on a sub-branch.
2. Author runs `-run=NamecMapBake -Map=<MapName>` on the reference PC → commandlet voxelises tiles or noise per tile with halo, runs the cave and ore passes, replays strokes through `FNamecVoxelWriteKernel`, runs the Requirement 10 checks, computes hashes, writes `Content/Map/Baked/VMA_<MapName>.uasset` (gitignored) → prints `MapHash`; the author records the hash in the handover note.
3. Author places `ANamecTown`, `ANamecCamp`, `ANamecRuin`, `ANamecBossArena`, `ANamecLootChestPoint`, `ANamecWaterVolume`, `ANamecExpansionRegion` and one `ANamecWorldSpawnPoint` on `L_Namec.umap`; towns, camps, ruins, arenas and standalone chest points receive a `StructureId` on placement → save runs `UNamecMapValidator` → failures block the save with actor and rule named → the level commits to plain git.
4. Player selects New World, enters name and settings → `UNamecWorldSave` is created with `MapId`, `MapRevision`, `MapHash` from `ShippedMapAsset`, empty deltas → lobby opens (`specs/multiplayer/multiplayer.md` Requirement 4).
5. Player selects Load World → `UNamecWorldLoader` applies Requirement 25 in order → on rule 2, compares the two hash tables, fills `PendingTerrainMarkers`, spawns one `ANamecTerrainUpdatedMarker` per pending chunk and shows "World updated to map revision N" once; no voxel data is read at load, and deltas apply per chunk in Data Flow 6.
6. As players move, `UNamecVoxelWorld` decompresses each needed chunk's base data from the map asset, applies its deltas, meshes and collides it (`specs/voxel-world/voxel-world.md` Requirement 4) → the chunk's PCG graph runs with seed `HashCombine(AuthoringSeed, ChunkX, ChunkY)` and the exclusion volumes → trees, forage, pickups and rocks appear identically on host and clients.
7. A player digs → `ServerApplyTerrainEdit` validates (tool tier, town radius, dig depth from baked base data, gated expansion regions) → `FNamecVoxelWriteKernel` writes the voxels → the delta is recorded and, if the chunk had no `EditedChunkBaseHashes` entry, the chunk's current base hash is recorded → replication as in `specs/voxel-world/voxel-world.md` Data Flow 3.
8. Benchmark (Phase 1): pipeline commits the hand-written benchmark stroke log and a `BakeSettings.json` for `Benchmark` with `HeightfieldSource` `Noise`, one region (Temperate Forest & Meadows) and one surface material → user bakes `VMA_Benchmark` → `L_Benchmark_SplitScreen` overrides its map asset to it → task 12 writes `results.json` and `content-manifest.json` → user pastes both, Researcher fills the Benchmark Results row including "Manifest hash".

## Edge Cases
1. When the stroke log has an unknown header version, a non-increasing `order`, an unknown `mode`, or an unknown `material_row`, the bake fails with exit code non-zero and prints the offending line number and reason; no asset is written.
2. When `HeightfieldSource` is `Tiles` and a heightfield or mask tile is missing, has the wrong bit depth, or its dimensions disagree with `BakeSettings.json`'s tile grid, the bake fails naming the tile; no asset is written. When `HeightfieldSource` is `Noise` and a mask tile is present anyway, the bake fails naming the unexpected tile.
3. When the Requirement 10 checks find an unreachable ore voxel or a cave with no surface connection, the bake fails and lists the first 20 violating voxels by map coordinate; no asset is written. The author fixes the heightfield or adds strokes and re-bakes.
4. When a stroke's sphere extends outside the world extent or below bedrock, the voxels outside are skipped and the rest of the stroke applies; the bake prints one warning per such stroke.
5. When a saved world's `MapId` matches but the shipped map's world extent is smaller than the save's chunk coordinates (the map shrank in a patch), deltas for chunks outside the new extent are kept in the save, not applied, and one log line per such chunk is written. They apply again if a later revision restores the extent.
6. When an expansion region unlocks and a chunk straddles the old boundary, deltas in that chunk replay onto the new base as in Requirement 25.2, and the chunk's mismatched base hash produces a marker like any other patched chunk.
7. When a player's terrain edit sphere overlaps a gated `ANamecExpansionRegion`, only the voxels inside the region are removed from the edit, the rest applies, and "Unexplored" shows in the acting player's viewport only (same shape as `specs/voxel-world/voxel-world.md` Requirement 35).
8. When two players interact with the same `ANamecTerrainUpdatedMarker` in the same frame, the server despawns it once and both clients see it disappear.
9. When the effective map asset (Requirement 4) fails to load at startup, the game shows "Map asset missing" on the main menu, disables New World, Load World and Join LAN Game, and leaves Characters, Settings and Quit usable.
10. When a LAN client's build has a different `MapHash` from the host's for the same `MapId` and `MapRevision` (including two developer machines with different bakes), the client is refused at join with "Host is running a different map build" (`specs/multiplayer/multiplayer.md` join validation), because chunk base data would differ and edits would not converge. Two developer machines converge by re-baking from the same commit.
11. When a client's build has a different `MapRevision` from the host's, the join is refused with the same message. Clients never apply deltas across a revision; the host applies them per chunk on stream (Requirement 29) after its own load rule (Requirement 25) has run.
12. When a save holds state keyed by a `StructureId` that no structure actor in the shipped level carries (the structure was removed in a revision), the entry is kept in the save, not applied, and one log line names the id. It applies again if a later revision restores an actor with that id.
13. When `UNamecMapValidator` runs and `Content/Map/Baked/VMA_<MapName>.uasset` is missing, every region-reading rule fails with "bake the map first" and the remaining rules still run and report.

## Acceptance Criteria
- [ ] Running `NamecMapBake` twice on the committed `Benchmark` inputs on the reference PC produces two byte-identical `VMA_Benchmark.uasset` files with the same printed `MapHash`.
- [ ] A fresh clone of the repository contains every file under `Content/Map/Source/`, no file under `Content/Map/Baked/` or `Content/Placeholder/`, and no `filter=lfs` line in `.gitattributes`.
- [ ] Staging a 21 MB file and committing is rejected by the pre-commit hook with the file name; staging a 19 MB file commits.
- [ ] A stroke log line with `mode` `Carve` fails the bake, printing that line number, and no asset is written.
- [ ] A test stroke log containing one `Fill` stroke whose `material_row` is an ore material, centred 7 m below the nearest base air voxel, fails the bake with that voxel's coordinate in the report; the same stroke centred 5 m below passes.
- [ ] The host and one LAN client streaming the same chunk log identical tree, forage node, loose pickup and collidable rock positions (position lists compared by an automation test after a 30 s settle), and a saved and reloaded world reproduces the same lists.
- [ ] New World shows name and settings inputs only; no seed or size input exists in the UI or in `UNamecWorldSave`.
- [ ] A world saved at `MapRevision` 1, loaded on a build shipping `MapRevision` 2 with one chunk's base changed under an existing dig, loads, keeps every dig, shows "World updated to map revision 2" once, and spawns exactly one `ANamecTerrainUpdatedMarker` in the changed chunk and none elsewhere.
- [ ] A world save whose `MapId` differs from the shipped asset is refused with "This world belongs to a different map" and the file is unchanged on disk.
- [ ] A world save whose `MapRevision` is higher than the shipped asset's is refused with "This world was saved with a newer version of the map".
- [ ] Digging into a gated `ANamecExpansionRegion` removes no voxels inside it, removes the voxels outside it, and shows "Unexplored" only in the digging player's viewport; a player walking into it is stopped at the boundary.
- [ ] Setting a gated region to `bGated` false, incrementing `MapRevision` and re-baking loads an existing save with every prior edit intact and no marker outside chunks that straddle the old boundary.
- [ ] Placing a third non-capital `ANamecTown` for one kingdom, or one inside the Volcanic region, blocks the level save with the actor name and the rule number.
- [ ] Saving `L_Namec.umap` with two `ANamecBossArena` actors in the Desert region fails validation naming both actors.
- [ ] No PCG-placed tree, rock, forage node or loose pickup exists inside any town protected radius, camp radius, arena radius, spawn zone or expansion region after a 30 s settle (automation test counts overlaps and expects 0).
- [ ] `Saved/Benchmark/<timestamp>/content-manifest.json` exists beside `results.json` after a benchmark run and lists the benchmark map's `MapHash`.
- [ ] A save with one pending terrain marker, saved, quit and reloaded, spawns that marker again; interacting with it, saving and reloading spawns none.
- [ ] Duplicating an `ANamecCamp` in the editor gives the copy a different `StructureId`; setting two actors to the same id by hand fails validation with rule 10.
- [ ] A LAN client whose build has a different `MapHash` from the host at the same `MapRevision` is refused with "Host is running a different map build".
- [ ] In the baked benchmark asset, at least one cave air voxel exists below the surface and every ore voxel is within 6 m below base air, verified by an automation test that reads the asset.
- [ ] `grep -r "UNamecWorldGenerator\|world seed\|world size" specs/` returns no match outside `specs/authored-map/authored-map.md` and the roadmap's history notes.
